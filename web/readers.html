write a reader

A reader is a frontend: source text in, shared AST out. Wrap it around lang’s kernel and you get a native compiler for your syntax.

start with the SDK

This release runs on Linux x86-64 with glibc 2.41 or newer, not macOS, Windows, or ARM. You need /bin/sh, curl, sha256sum, XZ-capable tar, Clang and the system C development toolchain (headers, libc, startup objects and ld). Clang 19.1.7 built this release; use that version for this walkthrough. On Debian/Ubuntu, ask your administrator for clang-19 build-essential binutils xz-utils curl and put Clang 19 on PATH as clang.

Start in an empty directory. Download this existing release, check its SHA-256 before extracting, then keep the extracted SDK directory intact. You do not need Git, make, Python or a Lang source checkout.

curl --fail --location --output lang-0.1.0+e5b90e2f0538-x86_64-linux.tar.xz \

the complete reader

Save this as tiny.lang in my first reader:

// tiny.lang: `answer 42` becomes a native program.

include "std/tok.lang"
include "std/ast.lang"

reader tiny(text *u8) *u8 {
    var tokens *Tokenizer = tok_new(text);
    if tok_kind(tokens) != TOK_IDENT || !streq(tok_text(tokens), "answer") {
        tok_note_expected(tokens, "answer");
        tok_print_error(tokens, "tiny");
        return nil;
    }
    tok_next(tokens);
    if tok_kind(tokens) != TOK_NUMBER {
        tok_note_expected(tokens, "number");
        tok_print_error(tokens, "tiny");
        return nil;
    }

    var value *u8 = tok_text(tokens);
    tok_next(tokens);
    if !tok_eof(tokens) {
        tok_note_expected(tokens, "end of input");
        tok_print_error(tokens, "tiny");
        return nil;
    }

    return ast_main_i64(ast_number(value));
}

Accept the whole source before returning an AST. Whitespace and comments may follow the number; extra tokens must fail.

mint and run your compiler

The SDK compiles your reader into the native tinyc compiler. That compiler turns answer 42 into LLVM; Clang links the native program. These commands build your reader and program using the released compiler.

printf 'answer 42\n' > answer.tiny
"$SDK/bin/lang" compiler tiny tiny.lang -o tinyc
./tinyc answer.tiny -o answer.ll
clang -O2 answer.ll -o answer
status=0
./answer || status=$?
printf 'answer returned %s\n' "$status"
test "$status" -eq 42

After the compiler’s Wrote messages, expect answer returned 42. The program communicates its answer through its exit status. Clang may also print a target-triple override warning when linking.

try an error

printf 'answer nope\n' > malformed.tiny
./tinyc malformed.tiny -o malformed.ll

This command must fail with malformed.tiny:1:8: expected number in its diagnostic.

contributor path: build from source

For compiler development, install Git, GNU make, Python 3 and Clang with the system C toolchain. This separate path builds Lang from source:

git clone https://gitlab.com/ehrlich-b/lang
cd lang
make build
./out/lang_next new reader tiny
./out/lang_next compiler tiny tiny.lang -o tinyc
