make a language

A reader is a frontend: source text in, shared AST out. Wrap it around lang’s kernel and you get a native compiler for your syntax.

Start a named language in the browser → The workshop starts with a small grammar, its lowering function, and source you can change. Inspect the parse tree and shared AST, correct located errors, then save or export the entire workspace. Compilation stays in the tab.

$ git clone \
  https://github.com/ehrlich-b/lang
$ cd lang && make init

the 20-line reader

// tiny.lang: `answer 42` becomes a native program.

include "std/tok.lang"
include "std/ast.lang"

reader tiny(text *u8) *u8 {
    var tokens *Tokenizer = tok_new(text);
    if tok_kind(tokens) != TOK_IDENT || !streq(tok_text(tokens), "answer") {
        eprintln("tiny: expected `answer NUMBER`");
        return nil;
    }
    tok_next(tokens);
    if tok_kind(tokens) != TOK_NUMBER {
        eprintln("tiny: expected a number");
        return nil;
    }

    var body *u8 = ast_block1(ast_return(ast_number(tok_text(tokens))));
    return ast_program1(ast_func("main", ast_vec(), ast_type_i64(), body));
}

Compile and run the checked-in example:

$ ./out/lang run example/tiny/tiny.lang example/tiny/answer.tiny
$ echo $?
42

mint the compiler

$ ./out/lang compiler tiny example/tiny/tiny.lang -o tinyc
$ ./tinyc example/tiny/answer.tiny -o answer.ll

tinyc is the compiler. Your reader supplies syntax and lowering; the kernel supplies the type system, LLVM backend, native and wasm targets, and the ABI shared with every other reader.

a grammar is only the beginning

Generated parsers support named rules, ordered alternatives, sequences, groups, optional/repeated items, labeled branches, named captures, exact literals, custom token kinds and eof. Failed matches rewind. Use eof when a whole file must be consumed. Left recursion is rejected with a grammar location; use the precedence toolkit for expressions.

Recovery is an explicit reader decision: collect immutable diagnostics, synchronize at a safe statement delimiter, and refuse a partial program. The workshop demonstrates two errors in one source and correction through the same compiled reader. The browser can inspect the parse tree as well as the final AST.

how this compares with yacc and ANTLR

Bison/yacc generate LR-family parsers, with GLR and conflict-analysis tools available in Bison. ANTLR combines lexer generation and adaptive parser prediction, with supported left-recursive expression grammars, listeners and visitors. Lang uses ordered recursive descent: the first successful branch wins. It does not supply those algorithms, a generated regular-expression lexer, lexer modes, ambiguity analysis or automatic token-insertion recovery.

Lang adds the other half of language building: lower your syntax to a typed shared AST, compose readers, and mint a native compiler or compile a supported program to Wasm in the browser. The capability contract is concrete examples and executable acceptance tests, not a claim that every Bison or ANTLR grammar transfers unchanged.
