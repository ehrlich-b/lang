# Translation-unit size audit

Limits count bytes, not Unicode characters. The shared compiler host uses `LANG_HOST_MAX_BYTES` (16 MiB by default, payload bytes excluding the sentinel); see [PHASE_HOST.md](PHASE_HOST.md). Legacy backend buffers still count their sentinel in the allocation capacity. Text capacities include one NUL terminator; an input exactly at capacity minus one is valid only when the next read proves EOF. Read loops handle short reads. Oversized input never succeeds with a valid prefix. Diagnostics identify the path or stage and capacity; writes loop until complete or fail loudly. Limits bound resources, not language semantics.

| Path | Capacity | Behavior at exhaustion |
|---|---:|---|
| Main CLI, includes/requires, combined source, serialized AST input/output | Configured host payload budget | Versioned host error, nonzero |
| Generated reader stdin/stdout and dependency closure | Configured host payload budget | Complete read or versioned host error |
| AST-to-source renderer | 64 KiB initially, grows to host payload budget | ast-byte-limit at maximum |
| Split kernel / split reader input | 4 MiB / 1 MiB | Path diagnostic, nonzero |
| Legacy fixed-destination capture | Caller capacity minus sentinel | output-limit, never a successful prefix |
| LLVM output | 64 KiB initially, grows to configured host payload budget | Versioned byte-limit error identifying LLVM output; no successful prefix |
| Legacy assembly / per-function output | 4 MiB / 512 KiB | Existing fatal overflow diagnostics |
| Direct Wasm module/section/body | 8 MiB each | Existing Wasm overflow error; no successful module |
| Direct Wasm static string data | 1 MiB | Existing direct Wasm data diagnostic |

The direct Wasm include loader reserves one additional byte in its 1 MiB allocation (maximum content: 1 MiB minus two bytes). The Lang reader retains 16 parameters per function/lambda/macro and 16 arguments per call. It rejects the seventeenth item at its source token, before writing the array, with `parameter limit exceeded (maximum 16)` or `call argument limit exceeded (maximum 16)`. Serialized core AST uses counted arrays; backend capabilities still apply.

Top-level declarations, shared codegen registries (including globals, structs, functions, locals, strings, enums, effects, macros, readers and lambdas), and LLVM strings/lambdas start at 64 entries and double. Parallel visibility/module arrays grow together and preserve indices. Globals use their actual 40-byte record stride. Name and arity indices preserve the previous first-match lookup semantics without scanning all functions. String interning preserves first occurrence order and uses an injective byte encoding for keys, including embedded NULs. `src/compiler_tables.lang` checks multiplication and the 1 GiB per-allocation ceiling before allocation, charges retained growth allocations to the host memory budget, and reports `table-byte-limit`, `memory-budget` or `allocation-failed`. Old storage remains in the compilation arena because recursive lowering can retain pointers. The initial capacity is not a language limit.

The direct Wasm backend retains the registry limits in `src/limits.lang`; its module output remains fixed as listed above. Parser block/field/control structures, captures, include depth and legacy assembly buffers retain their existing bounds. Host source/AST byte, work, node and memory budgets remain independent of table growth. `LANG_HOST_MAX_NODES` sets a shared source-token (including EOF), provenance-entry and AST-node budget: 1,048,576 by default, configurable from 1 through 16,777,216. Invalid settings report `invalid-node-limit`; exhausted source, provenance and AST budgets report `source-nodes`, `origin-budget` and `ast-nodes`, respectively.

`test/run_profile_checks.py` exercises real file/AST/reader paths and instrumented small-capacity emitter probes. Host transport probes explicitly configure the payload budget; the former fixed 1/4/8 MiB capacities are boundary test sizes, not current host limits. `test/run_phase_host.py` also checks growth past the old capacities, worker duplex transport, and source identity failures. It verifies success at the boundary, a valid-prefix adversary beyond it, intended diagnostics and nonzero status. Negative output artifacts are retained for inspection, never renamed or deleted to turn a failure into success. LLVM and legacy streaming outputs can leave partial files on failure; a nonzero compiler exit always invalidates them.

## Compile scaling benchmark

`python3 benchmark/compile/gen.py --lines 10000 -o program.lang` produces exactly that many nonblank source lines, including structs, field access, functions and a chain of checked calls. The same deterministic generator supports 100000 and 1000000 lines; padding consists of executable local declarations.

`python3 benchmark/compile/bench.py --compiler out/lang_next --output evidence` emits those three sizes and records wall emit seconds, peak RSS in KiB, input/output hashes, compiler identity, host, commands and the 1M/100k ratio in `evidence/bench.json`. LLVM emission excludes clang/link time. The harness explicitly configures a 128 MiB host payload budget for both source and output and a 16,777,216-node budget; default CLI use retains 16 MiB and 1,048,576 nodes. The generated 1M input requires more than 5.59 million source tokens, exceeding the default node budget; both explicit settings are recorded in the report and shared by candidate and base runs. Memory and work accounts still apply independently. Nonzero emissions fail the benchmark and keep their logs and partial artifacts. The ratio must be at most 15. The harness validates `out/build-receipt.json` against the current HEAD, all recorded source inputs, preserved seed, compiler hash and emitted artifact before measuring; rebuild with `make build` after committing.

To compare self compilation, also provide `--base-root` (a clean checkout at `4b93dcaa32c177ed827fb7597b02d8431ace2dec`, with `out/version_info.lang` prepared) and `--base-compiler` (that base built from its preserved seed). Both build receipts must validate. Candidate and base each emit their own pinned sources on the same host, five runs each, with identical host budgets; the candidate median must be at most 1.10 times the base median. Keep generated sources, raw logs and `bench.json` outside the checkout. `--sizes 10000` exercises the fragment without claiming a full-size verdict. Both LLVM and AST fixed points and the complete LLVM/Wasm suites remain integration requirements.
